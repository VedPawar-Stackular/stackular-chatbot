# Stackular API — Backend Rules

Constraints for Claude Code when working inside `stackular-api/`. Read root `CLAUDE.md` for full project context.

## Hard constraints

- **Never run `manual_reindex.py`** in the repo root — it uses `bge-large-en-v1.5` (1024-dim) which breaks the `bge-small-en` index (384-dim). Use `POST /admin/reindex` instead.
- **Pinecone metric must stay `dotproduct`** — hybrid search breaks silently on cosine. Do not change `deps.py`.
- **No new pip packages** without adding to `requirements.txt` and confirming the venv is activated.
- **Do not change `INDEX_NAME` or `EMBEDDING_DIM`** in `deps.py` — changing either corrupts the existing index.

## Environment

- Activate venv before any Python command: `.\.venv\Scripts\activate`
- Backend runs on port 8000 via `uvicorn main:app --reload`
- All secrets live in `stackular-api/.env` — never hardcode keys

## Key invariants

- `CHAT_HISTORY` is intentionally in-memory (dict keyed by session_id) — lost on restart by design
- Python 3.14 Pydantic V1 warning from LangChain is non-blocking — do not attempt to suppress or pin
- `bm25_params.json` is auto-generated by `build_index_if_empty()` — never edit it manually
- alpha=0.7 in hybrid search = 70% dense / 30% BM25 — don't change without benchmarking

## Reindex workflow

1. Edit `knowledge_base.md` in repo root
2. `POST /admin/reindex` with header `X-Admin-Token: <token from .env>`
3. `GET /health` — confirm `vectors_in_index > 0`

## Testing

- `python verify_rag.py` — tests retrieval quality
- `python verify_response.py` — tests end-to-end response quality
- No pytest suite yet; manual verification scripts are the test harness
